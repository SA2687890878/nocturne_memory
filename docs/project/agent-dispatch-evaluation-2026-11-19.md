# V4.0 Agent 记忆调度验收集（2026-11-19）

## 验收目标

验证 Agent 能否在任务开始时正确选择“不检索 / FTS 搜索 / 语义候选 / 读取全文 / 写入记忆”，并贯彻摘要优先、按需披露和停止规则。此文件定义预期行为，不冒充客户端运行遥测；必须在 Claude/Deva 实际会话中记录真实工具调用后才能计算准确率。

## 任务矩阵

| # | 用户任务类型 | 预期调度 | 不应发生 |
|---:|---|---|---|
| 1 | 询问一个独立通用概念，例如 HTTP 429 的含义 | 不检索，直接回答 | 不调用 search_memory |
| 2 | 简单数学计算或单位换算 | 不检索，直接计算 | 不读取 Boot 之外的记忆 |
| 3 | 继续 Nocturne 当前迭代计划 | search_memory 搜索项目路线；摘要够用即停止 | 不重复读取已在当前上下文完整呈现的文档 |
| 4 | 询问之前确定的 Embedding 默认策略 | FTS 搜索对应决策；摘要足够则直接回答 | 不默认调用 semantic_search_memory |
| 5 | 询问某个历史配置文件、接口字段或具体参数 | FTS 搜索后 read_memory 读取对应正文 | 不凭摘要猜测具体字段 |
| 6 | 当前对话已包含完整代码和异常，要求定位原因 | 直接分析当前上下文 | 不为已提供的信息重复检索 |
| 7 | 用自然语言改写描述历史主题，FTS 未找到目标 | 调整关键词；必要时调用 semantic_search_memory，并核实候选；PARTIAL 兜底先看命中词，不默认加载摘要 | 不把向量距离当成相关性置信度；不展开弱相关 PARTIAL 候选 |
| 8 | 用户提出一条新的长期偏好 | 先搜索查重；已有同主题记忆优先更新，否则创建 | 不重复创建、不记录临时噪声 |
| 9 | 用户要求修改某条现有长期规则 | 搜索定位 → read_memory 读全文 → 精确更新 → 为新版本生成摘要 | 不跳过全文读取、不沿用旧版本摘要 |
| 10 | 用户要求删除某条记忆 | 精确定位并读取目标；确认用户明确授权后删除 | 不根据模糊描述猜 URI 或批量删除 |
| 11 | 询问两个历史决策是否冲突 | 搜索双方摘要；必要时读全文与适用条件 | 不自动覆盖或合并不确定冲突 |
| 12 | 搜索返回有效摘要且已足以回答 | 直接回答并停止 | 不为了“完整”展开全文或递归读取 L3 |

## 记录字段

每个真实任务至少记录：

- task_id、任务类型、是否需要记忆（人工标注）
- 预期工具序列、实际工具序列
- search_memory 调用次数、semantic_search_memory 调用次数
- read_memory 调用次数、读取的 Memory URI
- 是否重复读取、是否读取无关正文
- 回答是否使用了正确记忆证据
- 输入/输出 Token（客户端可提供时记录；否则标注 unavailable）

## 评价指标

- 调度准确率：实际是否符合预期“不检索/检索/展开/写入”决策。
- 无效检索率：独立任务中发生记忆检索的比例。
- 全文展开率：任务中 read_memory 次数 / 需要记忆的任务数。
- 过度展开率：摘要已足够仍读取全文的任务数 / 摘要足够的任务数。
- 重复读取率：同一任务重复读取同一 URI 的次数 / 全部 read_memory 次数。
- 证据命中率：最终回答是否命中人工标注的目标 Memory。

## 验收边界

- 本表是 12 条标准化验收场景，尚未在 Claude/Deva 实际客户端逐条执行。
- 当前可验证的是 HTTP MCP 服务端工具列表与 search_memory 实际调用；客户端 stdio 子进程需由客户端重载后再进行端到端采集。
- 不将模型主观自评当成运行日志；没有实际工具轨迹的指标必须标记为未测。
- 不为统计指标而增加后台遥测或 Token 账本，优先使用客户端已有调用记录。
