# Nocturne MCP 工具说明

工具描述面向模型调用决策，遵循“做什么 + 关键边界”，不重复实现细节。参数说明只保留用途、默认值和不可违反的限制。纯文案优化不改变调用契约；2026-11-20 的披露能力扩展见下方。

| 工具 | 简要说明 |
|---|---|
| `read_memory` | 按 URI 读取摘要、正文行段、全文或系统视图。detail="summary" 不查询正文；start_line/end_line 只交付指定正文行；原有单参数调用保持全文。 |
| `create_memory` | 在指定父节点下创建记忆。创建前先搜索，确认没有可复用的已有记忆。 |
| `update_memory_summary` | 保存指定记忆版本的 AI 摘要；传入空字符串可清除摘要。 |
| `update_memory` | 更新记忆正文或元数据。调用前必须先读取该 URI 的完整正文；仅更新传入的字段。 |
| `delete_memory` | 删除指定 URI 路径。删除前必须读取完整正文并确认确需删除；若存在不能安全删除的子节点，工具会返回处理提示。 |
| `add_alias` | 为已有记忆创建别名 URI；别名与原记忆共享同一份正文，不会复制内容。 |
| `manage_triggers` | 为记忆节点添加或移除触发词；触发词应已出现在记忆库正文中。 |
| search_memory | 关联任务先将自然语言压缩为2-5个关键词/短语，再做严格检索；首轮无自动 PARTIAL 兜底，必要时显式二次检索；摘要优先，不返回正文片段。 |
| `semantic_search_memory` | 显式语义检索；校验当前路径、版本和生命周期，直接交付预算内摘要；距离不代表相关性，确需原文证据再读行段或全文。 |
| `diagnose_memory_backend` | 检查当前 MCP 进程对记忆 SQLite 数据库的读写能力；写入测试会回滚，不修改记忆数据。 |
| `sync_semantic_index` | 增量同步语义索引。可能调用配置的 Embedding API；API 失败时保留原索引。 |

## 调用边界

- 关联任务才调用 `search_memory`；自然语言问题先压缩为2-5个有区分度的关键词/短语，不直接提交完整问题长句。默认只交付元数据和摘要；需要原文时再调用 `read_memory`。
- 已知 URI 或纯定位/列表/路径核对可显式设置 `token_budget=0`，只取 L0；需要判断陌生候选是否相关时保留默认摘要预算取 L1。不要将 0 预算设为全局默认。
- `semantic_search_memory` 返回近邻候选及预算内当前摘要，不是相关性判断；先用返回摘要核对主题，摘要够用即停止，不再为同一摘要调用一次 read_memory。
- `create_memory` 前先搜索已有记忆，优先复用或更新，避免重复。
- `update_memory` 和 `delete_memory` 前必须读取完整正文。
- `sync_semantic_index` 是显式操作，可能调用配置的 Embedding API。
- 文案精简不改变参数 Schema、默认值、权限控制或业务行为。


## 正文读取预算（2026-11-19）

- system://index/<domain> 是 URI 导航地图，不是待读清单；禁止逐条展开整个 domain 或递归读取全部子节点。
- 每项任务默认最多读取 3 条直接相关正文；用户明确要求完整盘点/导出时才突破。
- 优先读取项目主入口；摘要足够回答或推进任务时立即停止。

## 按 URI 分层读取（2026-11-20）

- read_memory 新增可选 detail="full"、start_line=null、end_line=null，原有 uri 参数和全文默认行为保持兼容；工具总数仍为 11。
- detail="summary" 使用既有 search_summary_token_budget（默认 1200）控制摘要正文，不查询记忆正文、子节点和触发词；缺失时返回 MISSING，不自动展开。
- start_line/end_line 从 1 开始且包含两端，返回 Memory ID、总行数和原始行号；行段交付不附带子节点或触发词。
- 部分读取不等于已读全文；允许同版本补读尚未获取的层级/行段，修改前仍须完整读取。
- 默认严格搜索不生成 SQL 正文片段；显式 PARTIAL 仍保留内部有界片段证据，避免改变覆盖率与候选排名。
- 客户端需正常重载 MCP 才能看到新增参数；独立 stdio 快照验证不能证明既有客户端会话已重载。

## 语义候选与运行态收敛（2026-11-20 后续）

- semantic_search_memory 新增可选 token_budget；总工具数仍为 11。当前 namespace/路径/版本/生命周期先校验，别名按节点去重，再返回 L0/L1；服务端不查询正文。
- 已修复真实 stdio 中 sqlite_vec 可选 NumPy 导入阻塞：直接加载包内 vec0 扩展，并用兼容的 struct float32 序列化，向量文件格式不变。
- 工作库索引已增量更新 3 项，59/59 路径的版本、完整同步 hash 和元数据全部一致；真实 stdio + NVIDIA 查询已命中新记录 Top1。
- 最终验收见 [核心链路可用验收](./memory-core-ready-2026-11-20.md)；客户端文件规则更新不等于既有进程已重载。
