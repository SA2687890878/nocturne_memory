# 记忆系统迭代方案 V3

**版本日期：2026-10-28。状态：方案定稿，待用户批准，未实施。**

本次只交付方案文档。方案批准不等于活动库升级授权。
Markdown 是方案源文档，HTML 是同源阅读版。

## A 目标、范围与核心决策

### 1. 要解决的问题

正文里的“检索词”没有自动写入原生 Keywords。
正文里的“状态”也没有数据库字段约束。
前者混淆了检索文本与关联触发词，后者混淆了业务状态与内容。

本轮目标：**状态有唯一字段，关键词复用原生能力，治理可预览、可审查、可恢复。**

### 2. 成功标准

| 目标 | 验收口径 |
|---|---|
| 状态唯一真源 | 生命周期只认 Node 字段；正文不再承担机器状态 |
| 别名一致 | 同一 Node 的全部别名共享状态 |
| 内容与状态解耦 | 只改状态，不新增 Memory 内容版本 |
| 关键词不重复建设 | 只维护原生 glossary_keywords，不新增平行关键词字段 |
| 召回不误导 | 默认召回排除 obsolete，显式访问仍可见并警示 |
| 审查与回退 | 纯状态改动可见、可批准、可安全回退 |
| 升级可控 | 新库与旧库定义一致；中断后可受控重跑 |
| 治理不越权 | 逐条预览、单独批准；不重写历史、不自动清空待审池 |

### 3. 选型与取舍

| 议题 | 采用方案 | 不采用方案及理由 |
|---|---|---|
| 状态归属 | Node.lifecycle_status | 不放 Memory：避免随内容版本漂移；不放 Edge：避免别名分裂 |
| 关键词 | 原生 Glossary 绑定 | 不把正文检索词全量搬入：原生绑定还会产生跨记忆链接 |
| 审查展示 | 复用 before_meta/current_meta | 不新增一套并行状态差异协议 |
| 约束验证 | 固定定义、有限反射、隔离行为测试 | 不解析跨引擎 CHECK SQL，不比较反射全文 |
| 历史兼容 | 保留历史内容，恢复后给提示 | 不批量改写历史版本 |

### 4. 非目标

- 不新增依赖、关键词编辑存储或搜索索引状态副本。
- 不新增状态机、自动状态推断、TTL、自动归档或向量搜索。
- 不新增通用迁移锁平台、SQL 解析器或业务工作流引擎。
- 不重做整个 Review、权限体系或数据库架构。
- 不物理删除业务记忆，不恢复旧记忆系统或跨库合并。
- 不以迁移、验证或治理为由自动批准现有待审改动。

## B 数据模型、接口与写入语义

### 5. 状态定义

| 存储值 | 界面标签 | 含义 | 默认召回 |
|---|---|---|---|
| active | 在用 | 当前有效、仍在使用 | 包含 |
| completed | 已交付 | 工作已交付，仍有参考价值 | 包含 |
| obsolete | 已过时 | 不应默认作为当前依据 | 排除 |
| unspecified | 未标注 | 尚未明确分类，不等于失效 | 包含 |

四种值可按明确意图直接互改。
不引入转换审批状态机，也不把 completed 自动转为 obsolete。

### 6. Schema

新增 `Node.lifecycle_status`：

- 类型：`String(16)`。
- `nullable=False`。
- 数据库级 `server_default='unspecified'`。
- 显式命名 CHECK：`ck_nodes_lifecycle_status`。
- CHECK 只允许上表四种值。

以下是**拟议定义，不是已执行 SQL**：

```sql title="生命周期字段 · 设计示意"
lifecycle_status VARCHAR(16) NOT NULL DEFAULT 'unspecified'
  CONSTRAINT ck_nodes_lifecycle_status
  CHECK (lifecycle_status IN ('active', 'completed', 'obsolete', 'unspecified'))
```

模型创建新库与 015 升级旧库必须同形。
只设置 Python 默认值不算满足要求。
本轮不新增状态索引；不为四值字段预设性能收益。

`Memory.deprecated` 与 `migrated_to` 继续管理内容版本替换。
它们不表示业务生命周期，不与 obsolete 自动映射。

### 7. 公共接口契约

MCP、REST 和图服务使用同一个字段名 `lifecycle_status`。
新增字段不改变既有 URI、别名、namespace 或鉴权规则。

| 操作 | 输入或输出语义 |
|---|---|
| 创建 | 新增可选 lifecycle_status；省略时为 unspecified |
| 创建显式 null | 拒绝，不向 NOT NULL 字段写空值 |
| 更新省略或 null | 不修改现有状态 |
| 更新 unspecified | 明确清除已有分类，设为未标注 |
| 更新相同状态 | 成功但无状态净变化，不制造待审记录 |
| 更新非法值或空串 | 沿用现有参数错误通道拒绝；不得静默降级 |
| search_memory | 新增 include_obsolete=false；true 时同时搜索过时条目 |
| 直接读取/浏览结果 | 返回或展示 lifecycle_status；nav_only 也返回 |
| Review 差异 | 在现有 before_meta/current_meta 中增加该键 |

创建函数参数默认取字符串 `unspecified`，不用 None 表示省略。
省略由默认参数承接；显式 null/None 按非法输入拒绝。
更新参数仍允许 None，语义是不修改状态。

MCP create_memory/update_memory 及 REST 创建、更新请求都需补齐字段。
图服务所有“至少修改一项”的入口判断须允许纯状态更新。
省略状态时，旧调用保持原有内容与元数据更新行为。
不借本次变更重定义其它空更新语义。

参数校验只是第一层，数据库约束是最后防线。
错误不得吞成成功响应。

### 8. 写入与版本数据流

1. 校验输入与既有访问边界。
2. 定位 URI 对应的 Node。
3. 在原有事务中读取并更新该 Node 状态。
4. 只在内容实际变化时创建 Memory 版本。
5. Agent 写入沿用原有 rows_before/rows_after 记录。
6. 人工 Web 编辑保持既有行为，不新增 Agent 变更池记录。

内容、状态、priority、disclosure 的组合更新共用原事务。
状态属于 Node；priority/disclosure 仍属于路径关联的 Edge。
不得为更新别名分别复制状态。

普通内容版本恢复不修改生命周期。
旧内容正文恢复出“状态:”时，只作为历史残留提示。

### 9. 界面与工具说明

- 复用现有创建、编辑界面，增加四值选择，不新建管理面板。
- 浏览与直接读取显示状态；obsolete 给出清晰警示。
- MCP 工具说明解释四值、null 语义及默认召回差异。
- 不将状态字段拼回正文作为第二份可编辑真源。
- 状态选项显示中文标签，传输与存储使用英文值。

## C 召回、关键词与审计口径

### 10. 召回矩阵

| 入口 | 默认对 obsolete 的处理 | 额外约定 |
|---|---|---|
| 全文搜索 | 排除 | 仅此入口新增 include_obsolete 开关 |
| system://recent | 排除 | 不新增第二个可配置开关 |
| random | 排除 | 在随机排序与 LIMIT 前过滤 |
| Glossary 自动关联 | 排除 | 不产生指向过时目标的默认关联 |
| 显式 URI 读取 | 保留 | 展示状态与警示，不伪装成不存在 |
| 树、索引、浏览导航 | 保留 | 用于定位和治理；显示状态 |
| Boot 显式配置 URI | 保留 | 警示过时引用，Loaded 统计真实成功加载数 |

状态过滤应在排序、去重和 LIMIT 之前完成。
不得先取满结果再删除，否则会漏掉后续有效条目。
过滤依赖 Node 状态，不新增可编辑索引副本。

父节点 obsolete 不自动使子节点 obsolete。
别名指向同一 Node，因此召回过滤结果一致。
completed、active、unspecified 不因本轮变更被排除。

Boot 不静默改写配置、不伪报 Loaded，也不自动级联删除。
未加载的错误仍按原有错误路径报告。

### 11. 原生关键词的边界

原生 `glossary_keywords` 同时支持搜索和正文触发关联。
正文“检索词:”只是可搜索文本，不会自动变成原生绑定。
`search_documents.search_terms` 是派生数据，不是人工编辑入口。

本轮只使用已有原生绑定能力。
不新增 tags、search_keywords 或第二套关键词编辑器。

每个候选词按以下顺序判断：

1. 先审查并预览清理后的最终正文。
2. 沿用原生规范化与去重规则。
3. 沿用现有审计器的词频统计口径。
4. 检查命中频率小于 5%、绑定数量不超过 2。
5. 核对真实正文触发源与关联目标是否有用。
6. 通过逐项预览后，再决定是否绑定。

“全文能搜到”不足以证明值得绑定。
不得用泛词提高覆盖率，也不得补造句子制造触发源。
词频与绑定数合格，也不能替代关联语义审查。

只适合检索的表达保留在自然正文中。
删除旧模板时，不丢失有用检索表达，也不机械搬入 Keywords。

### 12. 审计分类

| 检查 | 数据来源与处理 | 是否影响失败退出 |
|---|---|---|
| entries_without_status | 改读字段，unspecified 为待标注提示 | 否，加入 ADVISORY_CHECKS |
| 模板状态残留 | 识别旧专用头部或专用元数据行 | 否，只提示，不自动修复 |
| 正文状态与字段冲突 | 字段为唯一真源，列出冲突 | 否，只提示 |
| 过时 Boot 引用 | 核对显式配置与 Node 状态 | 否，只提示 |
| 既有结构、关联、索引错误 | 保持原检查与 issue_count 口径 | 是，仍为硬错误 |
| 状态非法或 NULL | API/图服务校验与数据库约束拒绝 | 不允许写入形成正常状态 |

entries_without_status 继续沿用现有 namespace、叶节点和 Boot 豁免范围。
迁移预览不因此漏掉用户批准处理的容器或 Boot 条目。
审计 schema 前置检查增加该字段依赖。
缺表、缺列或索引漂移不得借 advisory 降级。

正文中的普通业务叙述、引用和代码块不是模板头部。
识别有歧义时保留原文并交人工审查。

## D 变更池、差异展示与安全回退

### 13. 快照净变化

继续保存完整 Node 快照，不删除 last_accessed_at。
仅在 `_rows_equal` 比较两边都存在的 nodes 行时忽略该键。
创建/删除的 None 语义保持不变。
其它表与其它字段继续按原规则比较。

这样，“改状态→读取更新访问时间→改回状态”应归零。
访问时间变化不应产生虚假的业务待审改动。

沿用 record_many 的语义：首次 before 冻结，后续 after 替换。
不另建一份状态专用 changeset。

### 14. Review 可见性

- 将 lifecycle_status 加入现有 before_meta/current_meta。
- 复用字典比较，使纯状态变更触发 has_changes。
- ReviewPage 的既有元数据键列表增加 lifecycle_status。
- 保持 ChangeGroup 摘要契约，不新增平行状态差异字段。
- 批准与回退入口均可看到状态前后值。

旧快照缺少状态键时显示为旧格式信息。
不得将“缺键”自动解释为 unspecified 并写回当前状态。

### 15. 状态回退的比较并交换

对已有 Node，设 before 为首次快照状态，after 为待审状态。
回退只处理 lifecycle_status，不比较或回写 last_accessed_at。

| 回退时当前状态 | 行为 |
|---|---|
| 等于 after | 用带状态条件的 UPDATE，将 after 改回 before |
| 等于 before | 无需写入，按已回到目标状态处理 |
| 与两者都不同 | 报冲突，整个 DB 变更组回滚 |
| 条件 UPDATE 未命中 | 视为并发冲突，整个 DB 变更组回滚 |
| 旧快照缺少状态键 | 跳过生命周期恢复，保留当前状态 |

条件更新只 SET 生命周期字段，不恢复整行 Node。
不得依赖无条件赋值覆盖人工修改。

冲突时不提交组内其它数据库改动，也不移除待审组。
只有数据库组成功后，才沿用原机制移除对应 JSON keys。
现有新建节点回退逻辑不扩大；批量治理不调用其物理删除路径。

### 16. 非原子边界

数据库事务与 JSON changeset 不是一个原子事务。
本轮不把它重构成新的存储系统。

若数据库已提交而 JSON 保存或清理失败：

- 停止当前批次，标明失败阶段。
- 同时核对数据库实际值与源 changeset。
- 保留待审资料，禁止盲目重复操作。
- 根据已确认的实际结果决定恢复或继续。

仅生命周期回退的 CAS，不代表全部历史回退已解决并发问题。
本轮不承诺修复其它元数据的既有并发语义。

## E 数据库迁移、备份与部署门禁

### 17. 015 迁移

拟新增 `backend/db/migrations/015_add_node_lifecycle_status.py`。
这是规划新增文件，当前尚不存在。

旧表使用一次 ADD COLUMN，同时加入类型、默认值、NOT NULL 和 CHECK。
不以“先加裸列、后补约束”的多步过程留下中间弱约束。
已有数据通过默认值成为 unspecified，不从正文自动推断。

新库仍沿用 create_all 后运行 migrations 的启动路径。
因此 015 必须识别已经由新模型创建的列。

幂等存在性检查只检查：

- SQLAlchemy 反射类型属于 String。
- nullable 为 false。
- 有数据库默认值，包含精确引号字面量 `'unspecified'`。
- 允许 PostgreSQL 默认值里的类型转换表达形式。

不比较 CHECK 反射全文，不比较默认值 SQL 全文。
不编写通用 SQL 解析器。
固定模型/DDL 与同引擎隔离测试共同证明约束行为。

本方案只保证受控建库、升级和重跑路径。
不审计人工篡改的同名约束或任意默认值表达式。
首次现场预检发现方案外已有字段时停止，交人工核对。
本次受控中断后的重跑，按已记录现场与幂等检查处理。

### 18. SQLite 备份修正

现有 WAL 场景不能仅 copy2 主数据库文件作为可靠备份。
迁移前改用标准库 SQLite online backup。

1. 在线程内创建只读源连接，并核对实际源文件。
2. 将备份写入唯一命名的 pending 目标文件。
3. 对备份执行 integrity_check，要求结果为 ok。
4. 校验成功后才发布为可用备份。
5. 失败时保留带失败标识的产物，停止迁移。

不覆盖旧备份，不删除失败证据。
不复用主线程 SQLite 连接跨线程操作。
数据库与源 changeset 必须配套备份和配套恢复。
备份副本的新数据库标识可能对应空变更池，不能代表源池干净。

### 19. 单一迁移执行者

部署前停止其它可能初始化数据库的 Web、MCP 和自动重连入口。
确认只有一个执行者后再升级。
无法确认就停止，不并发试跑。
本轮不新增通用分布式迁移锁。

对每次写库，在同一连接核对引擎与实际目标：

- SQLite：核对 PRAGMA database_list 中主库路径。
- PostgreSQL：核对 current_database() 与预期目标。
- 同时确认业务 namespace，不擅自跨命名空间治理。
- 核对失败立即停止；日志不得输出完整凭据。

引擎规则先加载，目标与授权先确认。
SQL Server 的 DB_NAME() 不机械套用于 SQLite/PostgreSQL。
业务库不执行无效值探测或测试建表。

### 20. 启动与恢复

| 阶段 | 必须满足的条件 |
|---|---|
| 升级前 | 单执行者、已核对目标、有效备份、源变更池已核对 |
| 升级后 | 字段/schema 与迁移记录正确、完整性通过 |
| 恢复服务 | 再启动其它 Web/MCP 入口，核对实际读写与工具 schema |
| 验收 | 不把“端口已开”视为迁移成功 |
| 失败恢复 | 停服务，配套恢复数据库与源 changeset，再用匹配版本代码启动 |

现有启动入口可能捕获初始化异常后继续运行。
部署必须显式核对迁移结果，不仅检查进程或 HTTP 可达。
不设计删除新列的在线降级；优先使用已验证备份恢复。

PostgreSQL 未经真实同引擎验证，不批准 PostgreSQL 部署。
其备份恢复使用经确认的 PostgreSQL 方案，不套 SQLite 文件备份。
本轮不凭“安装了驱动”宣称 PostgreSQL 已验证。

## F 存量治理与授权边界

### 21. 治理预览

先生成具体清单，不直接批量修改。
每个条目至少列出以下信息：

| 类别 | 必需信息 |
|---|---|
| 身份 | Node、涉及 URI/别名、业务 namespace |
| 状态 | 当前字段、旧模板状态、建议新值、冲突或歧义 |
| 正文 | 修改前后正文差异、保留的有效信息 |
| 关键词 | 增删绑定、规范化结果、频率、绑定数量、真实触发源 |
| 待审 | 源 Review 组及实际关联成员、是否交叠 |
| 回退 | 对应数据库与源 changeset 备份标识、失败停止点 |

正文历史标签的候选映射：在用→active，已交付→completed，已过时→obsolete。
这是预览建议，不是自动推断规则。
无明确标签、多个标签或语义冲突，均留给用户逐项决定。

仅清理获批条目当前版本中的专用“状态:”与“检索词:”模板。
不删除业务叙述，不改历史版本，不为提升关联覆盖率补造正文。
未获批条目保持原样，unspecified 合法存在。

### 22. 待审交叠门禁

按现有 Review 真实分组及实际成员检查交叠。
不能只按 URI 字符串比较；别名、共享 Node、关联行也要覆盖。

存在交叠即停止相应治理，交用户决定现有待审项如何处理。
不自动批准、清空或回退现有组。
不把治理所用数据库副本的空变更池当成源池状态。

仅在用户已解决交叠、确认预览与备份后执行获批项。
